> 普通请求 = 纯文本输入，走标准 vLLM v1 调度与执行链路

## 一、总体流程图

```mermaid
flowchart TD
    U1([🧑‍💻 用户提交请求<br/>纯文本 prompt]) --> S1

    S5 -->|否| S7
    
    S6["调度 RUNNING 请求<br/>继续生成未完成的请求"] --> S8
    S7["调度 WAITING 请求<br/>将新请求从 waiting 移入 running"] --> S8
    
    S8["构建 SchedulerOutput<br/>封装本 step 所有调度信息"] --> E1

    S12["组装 EngineCoreOutput<br/>将新生成 token 回传 Frontend"] --> U2
    
    U2([🧑‍💻 用户收到响应<br/>完整文本或流式 chunk])
```

## 二、Phase 1：请求接收与入队

```mermaid
flowchart TD
    A([用户提交 HTTP 请求]) --> B["Frontend HTTP Server<br/>接收请求并解析参数"]
    B --> C["提取关键字段：<br/>· prompt / messages<br/>· temperature / top_p<br/>· max_tokens<br/>· stream（是否流式）"]
    C --> D["LLMEngine.generate()<br/>创建生成任务"]
    D --> E["将 prompt 编码为 token_ids<br/>调用 tokenizer 分词"]
    E --> F["创建 Request 对象<br/>包含：<br/>· request_id<br/>· prompt_token_ids<br/>· sampling_params<br/>· max_tokens"]
    F --> G["Scheduler.add_request(request)<br/>➕ 请求入队"]
    G --> H["self.waiting.add_request(request)<br/>按到达时间或优先级排序"]
    H --> I["self.requests[request_id] = request<br/>建立全局索引"]
    I --> J([请求处于 WAITING 状态<br/>等待调度])
```

**关键函数**：`vllm/v1/core/sched/scheduler.py::add_request()`

```python
def add_request(self, request: Request) -> None:
    # 将请求加入等待队列，按 SchedulingPolicy 排序
    self.waiting.add_request(request)
    # 建立 request_id 到 Request 对象的映射
    self.requests[request.request_id] = request
    if self.log_stats:
        request.record_event(EngineCoreEventType.QUEUED)
```

## 三、Phase 2：调度器主循环

### 3.1 schedule() 主入口

```mermaid
flowchart TD
    A["Scheduler.schedule()<br/>🚀 调度入口，每个推理 step 调用一次"] --> B["self.kv_cache_manager.new_step_starts()<br/>🔄 新 step 开始，重置前缀缓存状态"]
    B --> C["初始化 token_budget = max_num_scheduled_tokens<br/>本 step 最多可处理的 token 数"]
    C --> D["第一阶段：调度 RUNNING 请求<br/>遍历 self.running 列表"]
    D --> E["第二阶段：调度 WAITING 请求<br/>遍历 self.waiting 队列"]
    E --> F["第三阶段：构建 SchedulerOutput<br/>封装所有调度结果"]
    F --> G["_update_after_schedule(scheduler_output)<br/>📊 推进各请求的 num_computed_tokens"]
    G --> H([返回 SchedulerOutput<br/>供 Executor 分发])
```

**关键函数**：`vllm/v1/core/sched/scheduler.py::schedule()`

```python
def schedule(self) -> SchedulerOutput:
    # 新 step 开始
    self.kv_cache_manager.new_step_starts()
    token_budget = self.max_num_scheduled_tokens
    
    # 1) 调度 RUNNING 请求（继续生成）
    for req in self.running:
        num_new_tokens = min(
            req.num_tokens - req.num_computed_tokens,
            token_budget
        )
        # 分配 KV Cache Blocks...
        token_budget -= num_new_tokens
    
    # 2) 调度 WAITING 请求（新请求）
    while self.waiting and token_budget > 0:
        req = self.waiting.peek_request()
        # 分配 KV Cache Blocks...
        self.running.append(req)
    
    # 3) 构建输出
    scheduler_output = SchedulerOutput(...)
    self._update_after_schedule(scheduler_output)
    return scheduler_output
```

### 3.2 RUNNING 请求调度

```mermaid
flowchart TD
    A["遍历 self.running 中的每个 request"] --> B["计算 num_new_tokens =<br/>request.num_tokens - request.num_computed_tokens<br/>还剩多少 token 要计算"]
    B --> C["num_new_tokens = min(num_new_tokens, token_budget)<br/>不能超过本 step 剩余预算"]
    C --> D["num_new_tokens = min(num_new_tokens,<br/>max_model_len - 1 - num_computed_tokens)<br/>不能超过模型最大长度"]
    D --> E["self.kv_cache_manager.allocate_slots(<br/>request, num_new_tokens)<br/>🧱 为新 token 分配 KV Cache Blocks"]
    E --> F{"分配成功?"}
    F -->|否| G["self._preempt_request(request)<br/>💥 KV 不足，抢占低优先级请求<br/>放回 waiting 队列"]
    F -->|是| H["scheduled_running_reqs.append(request)<br/>✅ 记录本 step 调度的请求"]
    H --> I["num_scheduled_tokens[req_id] = num_new_tokens<br/>记录各请求分配到的 token 数"]
    I --> J["token_budget -= num_new_tokens<br/>扣减预算"]
    J --> K([下一 RUNNING 请求])
    G --> K
```

**关键函数**：`vllm/v1/core/sched/scheduler.py::schedule()` 第一段循环

### 3.3 WAITING 请求调度

```mermaid
flowchart TD
    A["遍历 self.waiting 队列"] --> B{"len(self.running) >= max_num_seqs?<br/>是否已达到最大并发数?"}
    B -->|是| C["停止接纳新请求<br/>保持当前 running 集合"]
    B -->|否| D["request = self.waiting.peek_request()<br/>查看队首请求"]
    D --> E{"request.status?"}
    E -->|WAITING_FOR_REMOTE_KVS| F["KV Transfer 异步加载中<br/>跳过，稍后重试"]
    E -->|WAITING_FOR_FSM| G["结构化输出 grammar 编译中<br/>跳过，稍后重试"]
    E -->|WAITING| H["正常新请求"]
    
    H --> I["self.kv_cache_manager.get_computed_blocks(request)<br/>🔍 检查前缀缓存命中情况"]
    I --> J["计算 num_new_tokens =<br/>request.num_tokens - num_computed_tokens<br/>预填充阶段为 prompt 长度"]
    J --> K["self.kv_cache_manager.allocate_slots()<br/>分配 KV Cache Blocks"]
    K --> L{"分配成功?"}
    L -->|否| M["停止接纳<br/>等待下一 step"]
    L -->|是| N["self.waiting.pop_request()<br/>从等待队列移除"]
    N --> O["self.running.append(request)<br/>移入运行队列"]
    O --> P["request.status = RUNNING<br/>状态置为运行中"]
    P --> Q("num_scheduled_tokens[req_id] = num_new_tokens")
    Q --> R("token_budget -= num_new_tokens")
    R --> S([下一 WAITING 请求])
    F --> S
    G --> S
    M --> T([结束 WAITING 调度])
    C --> T
    S --> T
```

**关键函数**：`vllm/v1/core/sched/scheduler.py::schedule()` 第二段循环

### 3.4 调度后更新

```mermaid
flowchart TD
    A["_update_after_schedule(scheduler_output)"] --> B["遍历 num_scheduled_tokens<br/>每个被调度的请求"]
    B --> C["request.num_computed_tokens += num_scheduled_token<br/>推进已计算 token 数"]
    C --> D["request.is_prefill_chunk =<br/>num_computed_tokens < num_tokens<br/>判断预填充是否完成"]
    D --> E([更新完成<br/>Scheduler 状态与 Worker 同步])
```

**关键函数**：`vllm/v1/core/sched/scheduler.py::_update_after_schedule()`

```python
def _update_after_schedule(self, scheduler_output: SchedulerOutput) -> None:
    for req_id, num_scheduled_token in scheduler_output.num_scheduled_tokens.items():
        request = self.requests[req_id]
        request.num_computed_tokens += num_scheduled_token
        request.is_prefill_chunk = request.num_computed_tokens < request.num_tokens
```

## 五、Phase 4：状态更新与结果回传

### 5.1 Scheduler 更新输出

```mermaid
flowchart TD
    A["Scheduler.update_from_output(<br/>scheduler_output,<br/>model_runner_output)"] --> B["提取 sampled_token_ids<br/>按 req_id 映射到各请求"]
    B --> C["遍历 scheduler_output.num_scheduled_tokens"] --> D["_update_request_with_output()<br/>追加新生成的 token"]
    D --> E{"_check_stop(request, new_token_ids)<br/>是否触发停止条件?"}
    E -->|是| F["stopped = True<br/>原因：EOS / max_tokens / stop_str"]
    E -->|否| G["stopped = False<br/>请求继续生成"]
    F --> H["_handle_stopped_request(request)"]
    H --> I{"是否真的结束?<br/>非流式已完成 / 流式等待下一段"}
    I -->|是| J["_free_request(request)<br/>释放资源"]
    I -->|否| K["状态置为 WAITING_FOR_STREAMING_REQ"]
    J --> L["finished_req_ids.add(req_id)<br/>记录已完成"]
    G --> M([请求保留在 running<br/>下一 step 继续调度])
    K --> M
    L --> N([组装 EngineCoreOutputs<br/>返回 Frontend])
```

**关键函数**：`vllm/v1/core/sched/scheduler.py::update_from_output()`

```python
def update_from_output(self, scheduler_output, model_runner_output):
    for req_id, num_tokens in scheduler_output.num_scheduled_tokens.items():
        request = self.requests[req_id]
        req_index = model_runner_output.req_id_to_index[req_id]
        generated = model_runner_output.sampled_token_ids[req_index]
        
        # 更新请求状态
        new_tokens, stopped = self._update_request_with_output(request, generated)
        
        if stopped:
            finished = self._handle_stopped_request(request)
            if finished:
                self._free_request(request)
                self.finished_req_ids.add(req_id)
```

## 六、普通请求完整时序图

```mermaid
sequenceDiagram

    participant Frontend as Frontend
    participant Scheduler as Scheduler
    participant KV as KV Cache Manager
    participant Worker as Worker
    
    User->>Frontend: POST /v1/chat/completions<br/>prompt: "你好"
    Frontend->>Scheduler: add_request(Request)
    Scheduler->>Scheduler: waiting.add_request(req)
    
    loop 调度-执行-更新循环，直到请求完成
        Scheduler->>Scheduler: schedule()
        Note right of Scheduler: 1) 新 step 开始<br/>2) 调度 RUNNING / WAITING<br/>3) 分配 KV Blocks<br/>4) 构建 SchedulerOutput
        
        Scheduler->>KV: allocate_slots(request, num_new_tokens)
        KV-->>Scheduler: new_blocks
```

## 八、vllm-ascend 扩展点（普通请求同样生效）

| 扩展 | 生效函数 | 对普通请求的影响 |
|------|---------|---------------|
| 动态批处理 | `SchedulerDynamicBatch.schedule()` | 通过 `BudgetRefiner` 动态调整 token budget，decode-first 重排队列 |
| 重计算调度 | `RecomputeScheduler.schedule()` | P/D 分离时 KV 不足则将请求回退到 PD Proxy，普通请求同样受保护 |
| 负载均衡 | `BalanceScheduler.balance_gather()` | DP 场景下防止单 rank 过载，影响新请求接纳 |
| NPU 适配 | `NPUModelRunner.execute_model()` | 将 CUDA 算子替换为 NPU 算子，逻辑流程不变 |
