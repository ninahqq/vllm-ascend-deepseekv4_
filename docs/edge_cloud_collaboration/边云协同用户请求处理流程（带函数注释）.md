## 二、Phase 1：请求接收与调度（Scheduler 侧）

### 2.1 请求进入系统

```mermaid
flowchart TD
    A([用户提交 HTTP/gRPC 请求]) --> B["vLLM Frontend<br/>解析请求参数"]
    B --> C["LLMEngine / AsyncLLMEngine<br/>将请求封装为 Request 对象"]
    C --> D["Scheduler.add_request(request)<br/>➕ 将请求加入 waiting 队列"]
    D --> E["self.waiting.add_request(request)<br/>按 SchedulingPolicy 排序（FCFS / PRIORITY）"]
    E --> F["self.requests[request_id] = request<br/>建立 request_id 到 Request 的映射"]
    F --> G([请求已进入等待队列<br/>等待调度])
```

**关键代码位置**：`vllm/v1/core/sched/scheduler.py`（基类）或 `vllm_ascend/core/recompute_scheduler.py`（vllm-ascend 重载）

```python
# 简化示意
def add_request(self, request: Request) -> None:
    self.waiting.add_request(request)          # 加入等待队列
    self.requests[request.request_id] = request # 建立索引
```

### 2.2 主调度循环

```mermaid
flowchart TD
    A["Scheduler.schedule()<br/>🚀 主调度入口"] --> B["self.kv_cache_manager.new_step_starts()<br/>🔄 新 step 开始，重置 KV Cache 状态"]
    B --> C["第一阶段：调度 RUNNING 请求<br/>遍历 self.running 列表"]
    C --> D["第二阶段：调度 WAITING 请求<br/>遍历 self.waiting 队列"]
    D --> E["第三阶段：构建输出<br/>组装 SchedulerOutput"]
    E --> F["第四阶段：构建 Connector Metadata<br/>KV + EC 元数据"]
    F --> G([返回 SchedulerOutput])
```

**关键代码位置**：`vllm/v1/core/sched/scheduler.py::schedule()`

```python
def schedule(self) -> SchedulerOutput:
    self.kv_cache_manager.new_step_starts()
    # ... 调度 RUNNING ...
    # ... 调度 WAITING ...
    scheduler_output = SchedulerOutput(...)
    if self.connector is not None:
        scheduler_output.kv_connector_metadata = self.connector.build_connector_meta(...)
    if self.ec_connector is not None:
        scheduler_output.ec_connector_metadata = self.ec_connector.build_connector_meta(...)
    self._update_after_schedule(scheduler_output)
    return scheduler_output
```

### 2.4 _try_schedule_encoder_inputs 详细逻辑

```mermaid

    A["_try_schedule_encoder_inputs(<br/>request, num_computed_tokens,<br/>num_new_tokens, encoder_budget)"] --> B["遍历 request.mm_features<br/>每个多模态特征"]
    B --> C["计算 overlap =<br/>[num_computed_tokens, num_computed_tokens+num_new_tokens)<br/>∩<br/>[start_pos, start_pos+num_encoder_tokens)"]
    C --> D{"有重叠?<br/>当前 step 是否需要该 encoder 输出?"}
    D -->|否| E["break<br/>后续 encoder 更晚才用到"]
```

```python
def _try_schedule_encoder_inputs(self, request, num_computed_tokens,
                                  num_new_tokens, encoder_compute_budget):
    for i, mm_feature in enumerate(request.mm_features):
        # ... overlap 计算 ...
        if self.ec_connector is not None and self.ec_connector.has_cache_item(
            item_identifier
        ):
            external_load_encoder_input.append(i)  # 边云命中
            continue
        encoder_inputs_to_schedule.append(i)        # 本地计算
        encoder_compute_budget -= num_encoder_embeds
    return (encoder_inputs_to_schedule, num_new_tokens,
            encoder_compute_budget, external_load_encoder_input)
```

### 3.2 ModelRunner 中的 EC 生命周期（Context Manager）

```mermaid
flowchart TD
    A["ModelRunner.execute_model(<br/>scheduler_output)"] --> B{"has_ec_transfer()?<br/>是否启用边云协同?"}
    B -->|否| C["正常执行，无 EC 逻辑"]
    B -->|是| D["进入 maybe_get_ec_connector_output(<br/>scheduler_output, encoder_cache)<br/>Context Manager"]
    D --> E["ec_connector = get_ec_transfer()<br/>获取全局 EC Connector 实例"]
    E --> F["ec_connector.bind_connector_metadata(<br/>scheduler_output.ec_connector_metadata)<br/>绑定元数据"]
    F --> G{"ec_connector.is_consumer?<br/>本节点需从边云加载?"}
    G -->|是| H["ec_connector.start_load_caches(<br/>encoder_cache, **kwargs)<br/>☁️ 从边云加载 Encoder Cache"]
    G -->|否| I[跳过加载]
    H --> J["加载完成，encoder_cache[mm_hash] = tensor"]
    I --> J
    J --> K["try:<br/>&nbsp;&nbsp;yield output<br/>执行模型 forward"]
    K --> L["finally:<br/>&nbsp;&nbsp;清理逻辑"]
    L --> M["output.finished_sending, output.finished_recving =<br/>ec_connector.get_finished(<br/>scheduler_output.finished_req_ids)"]
    M --> N["ec_connector.clear_connector_metadata()<br/>解绑元数据"]
    N --> O([Context Manager 退出])
```

**关键代码位置**：`vllm/v1/worker/ec_connector_model_runner_mixin.py::ECConnectorModelRunnerMixin._get_ec_connector_output()`

```python
@contextmanager
def _get_ec_connector_output(scheduler_output, encoder_cache, **kwargs):
    output = ECConnectorOutput()
    ec_connector = get_ec_transfer()
    ec_connector.bind_connector_metadata(scheduler_output.ec_connector_metadata)
    
    if ec_connector.is_consumer:
        ec_connector.start_load_caches(encoder_cache, **kwargs)
    
    try:
        yield output
    finally:
        output.finished_sending, output.finished_recving = \
            ec_connector.get_finished(scheduler_output.finished_req_ids)
        ec_connector.clear_connector_metadata()
```

```python
    """
    Returns:
```

```mermaid
    EdgeScheduler->>EdgeScheduler: add_request(req1)
    EdgeScheduler->>EdgeScheduler: schedule()<br/>图片A无EC缓存
    EdgeScheduler->>EdgeWorker: SchedulerOutput<br/>encoder_inputs_to_schedule=[0]
    
    EdgeWorker->>EdgeWorker: _gather_mm_embeddings()<br/>Vision Encoder 计算图片A
    EdgeWorker->>EdgeWorker: forward() + sampling
    EdgeWorker->>Shared: save_caches(encoder_cache, mm_hash_A)<br/>💾 写入边云
    EdgeWorker-->>EdgeScheduler: ModelRunnerOutput
    EdgeScheduler-->>User: 返回请求1结果
    
    Note over User,CloudWorker: === 第二阶段：Cloud 端复用 EC 处理新请求 ===
    
    User->>CloudScheduler: 请求2: 相同图片A + 新文本
    CloudScheduler->>CloudScheduler: add_request(req2)
    CloudScheduler->>CloudScheduler: schedule()<br/>_try_schedule_encoder_inputs()<br/>ec_connector.has_cache_item(mm_hash_A) → True
    CloudScheduler->>CloudScheduler: external_load_encoder_input=[0]<br/>update_state_after_alloc()<br/>build_connector_meta()
    CloudScheduler->>CloudWorker: SchedulerOutput<br/>ec_connector_metadata={mm_hash_A}
    
    CloudWorker->>CloudWorker: bind_connector_metadata(meta)
    CloudWorker->>Shared: start_load_caches(encoder_cache)<br/>☁️ 读取 EC-A
    Shared-->>CloudWorker: 返回 tensor
    CloudWorker->>CloudWorker: _gather_mm_embeddings()<br/>直接复用 EC-A
    CloudWorker->>CloudWorker: forward() + sampling<br/>跳过 Vision Encoder
    CloudWorker->>CloudWorker: get_finished()<br/>clear_connector_metadata()
    CloudWorker-->>CloudScheduler: ModelRunnerOutput
    CloudScheduler-->>User: 返回请求2结果
```

## 六、vllm-ascend 扩展点标注

| 扩展功能 | 涉及类/函数 | 与 EC 的交互 |
|---------|-----------|------------|
| **动态批处理** | `SchedulerDynamicBatch.schedule()` | 在标准 EC 检查前，先通过 `BudgetRefiner.refine_budget()` 动态调整 token budget；采用 decode-first 策略重排 running 队列 |
| **重计算调度** | `RecomputeScheduler.schedule()` | 当 KV Consumer 内存不足时，传统 Scheduler 会 preempt，而 RecomputeScheduler 将请求加入 `recomputed_reqs`，通过 PD Proxy 回退到 Prefill 节点；EC 检查逻辑与基类相同 |
| **负载均衡** | `BalanceScheduler.balance_gather()` | 在 DP 场景下，schedule() 的 WAITING 阶段会检查 `balance_flag`，防止单 rank 过载；EC 元数据构建不受影响 |
| **MTP KV Consumer** | `RecomputeScheduler.add_request()` | 为支持 MTP（Multi-Token Prediction），填充 `spec_token_ids` 为 placeholder；EC 加载流程不受影响 |
| **Hybrid Model** | `RecomputeScheduler.add_request()` | 对 qwen3_next / qwen3_5 模型，作为 KV Producer 时会移除 prompt 最后一个 token；EC 的 save/load 流程独立 |
